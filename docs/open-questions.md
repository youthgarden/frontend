# 확인이 필요한 것

만들면서 문서만으로는 정할 수 없었던 것, 다른 사람과 합의해야 하는 것을 모았다. 답이 정해지면 해당 줄을 지우고 결과를 관련 문서(ADR, 명세)에 옮긴다.

## 맵 담당 팀원과 합의

2026-11-20에 프론트엔드를 "배우는 쪽"(조가을)과 "검증받는 쪽"(김균호)으로 나눴다([분담](ownership.md)). 이 분담은 조가을 본인의 확인을 아직 거치지 않았다.

| 번호 | 질문 | 지금 가정한 것 |
|---|---|---|
| 1 | `events.ts`에 추가한 이벤트 네 개(`player-level`, `place`, `map-connection`, `map-population`)와 `current()` 함수에 동의하는가 | "제안"으로 표시해 두고 쓰고 있다 ([ADR 0006](adr/0006-build-on-teammate-branch-and-event-contract.md)) |
| 2 | 맵의 파일을 고친 곳이 괜찮은가: `player.ts`(동그라미를 캐릭터로), `World.ts`·`Room.ts`(다른 접속자, 시험관, `goto` 구독 누수 수정), `PhaserGame.tsx`(내 캐릭터 정보 전달) | 배치, 충돌, 장면 전환, 안내 문구는 건드리지 않았다 |
| 3 | 맵의 이름표는 "강의실"이고 기획서와 화면은 "강의장"이다. 어느 쪽으로 맞추는가 | 화면은 기획서를 따랐다. 맵의 이름표는 그대로 두었다 |
| 4 | 건물 안에 있는 사람이 다른 사람에게 어떻게 보여야 하는가 | 문 앞에 서 있는 것으로 보인다. 건물 안에서는 다른 접속자가 보이지 않는다 |
| 5 | 캐릭터의 크기가 맵과 맞는가. 맵과 같은 2배로 그려 키가 약 124px다 | 그대로 두었다. 이름표만 1.5배로 줄였다 |
| 6 | 광장의 크기나 시작 위치가 바뀌면 `src/game/mapSpec.ts`도 함께 바꿔야 한다 (모의 서버가 읽는다). 두 곳에 같은 숫자가 있는 것이 괜찮은가 | `World.ts`의 값에 2를 곱해 `mapSpec.ts`에 적어 두었다. `World.ts`가 `mapSpec.ts`를 읽게 하면 한 곳이 되지만 맵의 파일을 더 고쳐야 해서 하지 않았다 |
| 7 | AI 시험관을 시험장 접수 책상 옆에 세웠다. 자리가 괜찮은가 | `Room.ts`에 네 줄을 넣었다. 장식이고 충돌은 없다 |

## 기획과 디자인

| 번호 | 질문 | 지금 가정한 것 |
|---|---|---|
| 8 | 와이어프레임(Figma)과 화면이 다른 곳은 어디인가 | Figma 파일에 접근 권한이 없어 열지 못했다. 화면은 기획서의 유저 플로우와 API 명세만으로 구성했다 |
| 9 | 기획서가 가리키는 `userflow.md`(단계별 상세 화면 반응과 예외 흐름)는 어디에 있는가 | 받은 문서 묶음에 없었다. 예외 흐름은 API 명세의 에러 코드에서 역으로 정했다 |
| 10 | 기획서는 "건물 안으로 들어가지 않고 화면 전환도 없다"고 적는데 실제 맵은 건물 안이 별도 화면이다. 기획서를 고치는가 | 맵 담당의 결정을 따랐다 |
| 11 | AI 시험관의 전용 그림이 나오는가. 골드 모자(`#ffd53d`)가 Lv.1 노랑 모자(`#fdd22e`)와 구분되지 않는다 | 골드 모자를 쓴 키트 캐릭터로 대신했다. 맵에서는 이름표의 "AI" 표시로 구분한다 |
| 12 | 미달한 과제를 바로 다시 볼 수 있는가, 횟수나 대기 시간 제한이 있는가 | 제한 없이 다시 볼 수 있다고 가정했다. 명세에 제한이 없다 |
| 13 | 키트의 `updateCharacter`가 Phaser 4에서 화면을 멈춘다. 키트를 만든 쪽에서 고쳐 줄 수 있는가 | 맵 쪽 연결 코드에서 우회했다 ([ADR 0002](adr/0002-vendor-pixel-kit.md)) |
| 14 | 루트의 `기획서/`, `설계/`, `청년 유치원 픽셀 키트/` 폴더를 이 저장소에 올리는가 | 올리지 않았다 |

## 백엔드와 합의

| 번호 | 질문 | 지금 가정한 것 |
|---|---|---|
| 15 | 캐릭터 외형을 서버에 저장할 계획이 있는가 | 없다고 가정하고 회원 번호로 정했다 ([ADR 0005](adr/0005-character-look-from-user-id.md)). 생기면 `GET /users/me`와 WebSocket 접속자 정보에 필드가 필요하다 |
| 16 | "지금 할 일"에 풀던 시험을 보여 주려면 맵에 들어올 때 `GET /attempts/current`를 불러야 한다. 이 API는 부를 때 자동 제출을 처리하는데, 맵 입장 때 불러도 되는가 | 부르지 않는다. 풀던 시험은 시험관에게 말을 걸어야 알 수 있다 |
| 17 | 강의 영상 5개의 유튜브 ID와 정확한 길이 | 1번은 임시 영상, 2~5번은 영상 없이 재생을 흉내 낸다 ([ADR 0008](adr/0008-lecture-player-adapter.md)) |
| 18 | 명세의 멀티플레이 좌표는 맵 하나를 전제로 한다. 건물 안이 별도 화면이 된 지금, 건물 안의 위치도 공유할 것인가 | 광장의 위치만 보낸다 |

## 명세에서 찾은 빈틈

모의 서버와 화면을 만들면서 명세만으로는 정할 수 없었던 곳이다. 백엔드와 맞춰야 한다. 모의 서버가 고른 동작은 [모의 서버 문서](mock-server.md)에 있다.

| 번호 | 빈틈 | 지금 고른 동작 |
|---|---|---|
| 19 | ERD에 `auto_submitted`를 담을 컬럼이 없는데 `GET /attempts/current` 응답에는 필요하다 | 모의 서버는 응시에 값을 따로 둔다 |
| 20 | 서버가 자동 제출할 때 `submitted_at`을 무엇으로 두는지 정해져 있지 않다 | 마감 시각 + 1분 |
| 21 | `GET /attempts/current`의 "안 본 결과" 대상이 두 곳에서 다르게 읽힌다. 규칙은 "결과를 안 본 가장 최근 응시"인데 응답 설명은 "자동 제출됨"만 말한다 | 규칙 쪽을 따른다. 직접 제출하고 채점 중에 나간 응시도 포함된다. 화면은 `auto_submitted`에 따라 문구를 나눈다 |
| 22 | `GET /attempts/{id}`가 시험 중인 응시를 받았을 때의 응답이 없다 | 점수 필드를 비워 응답한다 |
| 23 | `level_up.level`이 "현재 레벨"이라서, 지난 결과를 다시 볼 때 그 시험으로 몇 레벨이 됐는지 알 수 없다 | 화면은 지난 결과에서 숫자 없이 "레벨이 올랐어요"라고만 쓴다 |
| 24 | 시청 구간을 소수 초로 보내도 되는가 | 화면은 정수 초로 반올림해 보낸다 |
| 25 | 탭을 닫는 순간의 마지막 답안과 시청 구간을 보낼 방법이 없다. 답안은 최대 3초, 시청 구간은 최대 10초 분량이 빠질 수 있다 | 빠지는 것을 받아들였다. 필요하면 브라우저가 닫히면서도 보내 주는 전송 방식(`keepalive`)을 검토한다 |
| 26 | 응시가 이미 지워진 경우(다른 탭에서 포기)의 화면 동작이 명세에 없다 | 화면은 "더 이어 풀 수 없어요"라고 알리고 닫는다 |
