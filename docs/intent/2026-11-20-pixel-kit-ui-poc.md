# 의도: 픽셀 키트를 입힌 화면과 모의 서버

PoC(Proof of Concept)는 본격적으로 만들기 전에 방향이 맞는지 확인하려고 작게 만들어 보는 시제품이다. 이 작업은 PoC로 방향을 확인받은 뒤 같은 방향으로 완성했다. 이 문서는 이 작업이 **무엇을 확인하려는 것이고 왜 이런 모양인지**를 적는다. 어떻게 만들었는지는 [계획 문서](../plan/2026-11-20-pixel-kit-ui-poc.md)에, 개별 기술 결정은 [ADR](../adr/)에, 작업 중에 내린 판단은 [판단 기록](../decision-log.md)에 있다.

## 요청받은 것

1. "청년 유치원 픽셀 키트"를 화면에 적용한다.
2. 기획서를 보고 사용성 좋게 만든다.
3. 구현되지 않은 API는 모의 서버로 대신하고, 다양한 사용자를 다룬다.
4. 실제로 서버를 띄워 확인받은 뒤에 PR을 올린다. 먼저 PoC로 방향이 맞는지부터 확인한다.
5. 맵과 구역 구성은 다른 팀원이 진행 중이다. 캐릭터를 뺀 건물과 사물의 세부는 나중에 바뀔 수 있다.

## 확인하려던 것

| 질문 | PoC에서 보여 주는 것 |
|---|---|
| 키트의 그림과 색이 화면 전체의 겉모습이 될 수 있는가 | 로그인부터 레벨업까지 같은 색, 같은 테두리, 같은 캐릭터로 이어지는 화면 |
| 게임에 익숙하지 않은 사람도 맵에서 헤매지 않는가 | "지금 할 일" 카드와 이동 버튼, 첫 입장 안내 |
| 시험 화면이 30분 동안 쓰기에 편한가 | 과제·자료, AI 대화, 답안 세 영역과 타이머, 자동 저장 |
| 백엔드 없이 한 바퀴가 도는가 | 가입 → 강의 수강 → 시험 → 채점 → 레벨업이 모의 서버에서 실제로 동작 |
| 실제 맵과 실제 백엔드로 바꿀 때 무엇을 고쳐야 하는가 | 맵은 이벤트 일곱 개, 백엔드는 환경 변수 하나. 실제 맵은 이미 옮겼다 |

## 판단의 기준으로 삼은 것

### 1. 사용자는 게이머가 아니다

기획서의 페르소나는 무역 사무직을 준비하는 취업 준비생, 5년 차 해외영업 대리, 인사팀 과장이다. 2D 맵은 "배우는 곳과 검증받는 곳이 한곳에 있다"는 것을 느끼게 하는 장치이지, 넘어야 할 관문이 아니다. 그래서 맵을 걸어 다니는 재미는 살리되 **맵을 몰라도 다음 할 일에 닿을 수 있게** 했다.

- HUD의 "지금 할 일"이 다음 한 가지를 알려 준다. 강의를 들어야 하면 강의 제목을, 시험을 볼 수 있으면 과제 제목을 보여 준다.
- 이동 버튼을 누르면 그 건물 안으로 바로 간다. PoC에서는 캐릭터가 걸어가게 해서 길을 보여 주려 했으나, 실제 맵은 건물 안이 별도 화면이라 맵 담당이 정한 이동 방식을 따랐다. 이미 그 건물 안이면 버튼 대신 "위쪽 칠판 앞에서 F"라고 알려 준다.
- 강의 목록은 각 강의가 어떤 시험을 열어 주는지 알려 준다. 과제 목록은 막힌 과제마다 어떤 강의를 들어야 하는지와 그 강의로 가는 버튼을 준다.

### 2. 귀여움은 겉에, 읽기 편함은 속에

키트의 분위기는 제목, 버튼, 테두리, 캐릭터가 만든다. 과제 설명, 계약서, AI 답변, 답안, 피드백처럼 **문장으로 읽는 글은 평범한 고딕**이다. 시험 화면은 장식을 가장 적게 썼다. 이 서비스가 평가하는 것은 사용자가 자료를 읽고 AI의 답을 검증하는 과정이고, 그 과정은 읽기에서 시작한다.

### 3. 되돌릴 수 없는 일은 미리 말한다

- 시험을 시작하면 시간이 바로 흐르고, 나가 있어도 흐른다. 과제 안내에서 시작 전에 알린다.
- 포기하면 응시 기록과 대화가 삭제된다. 무엇이 사라지는지 보여 주고 한 번 더 묻는다.
- 제출하면 고칠 수 없다. 답안이 비어 있으면 그 사실을 따로 경고한다.
- 대화와 답안 수정, 붙여넣기, 창 이탈이 기록돼 평가에 쓰인다. 숨기지 않고 화면에 적는다.

### 4. 결과 화면은 다음 행동으로 이어진다

미달한 사람이 점수만 보고 나가지 않게 한다. 어느 항목이 부족했는지, 근거가 된 대화가 어느 장면인지, 무엇을 다시 보면 되는지를 한 화면에서 잇는다. 통과한 사람에게는 맵으로 돌아가면 모자가 바뀐다고 예고한다. 레벨업 연출은 이 서비스에서 움직임을 가장 많이 쓰는 유일한 곳이다.

### 5. 바뀔 것과 바뀌지 않을 것을 나눈다

| 바뀔 것 | 대비 |
|---|---|
| 맵, 건물, 사물의 배치와 모양 | 화면은 맵과 이벤트 목록으로만 주고받는다. 맵의 배치와 장면은 건드리지 않았다 |
| 백엔드 (아직 없음) | 화면은 명세의 주소만 부른다. 환경 변수로 실제 서버에 연결한다 |
| 강의 영상 (아직 없음) | 재생기를 한 겹 감쌌다. 영상 ID만 바꾸면 된다 |
| 캐릭터 외형 선택 (확장 계획) | 외형 규칙을 함수 하나에 두었다 |

| 바뀌지 않을 것 | 그래서 공들인 곳 |
|---|---|
| 캐릭터와 레벨별 모자 색 | 캐릭터를 그리는 코드를 맵과 화면이 함께 쓰는 모듈로 분리 |
| API 명세의 주소와 형식 | 타입과 통신 코드를 명세와 1:1로 맞춤 |
| 평가 방식 (네 항목, 80점 통과) | 과제 안내, 시험 화면, 결과 화면이 같은 네 항목을 같은 이름으로 보여 줌 |

## 일부러 하지 않은 것

| 하지 않은 것 | 이유 |
|---|---|
| 맵의 배치, 충돌 처리, 장면 전환 | 맵은 다른 팀원의 작업이다 |
| 상담실, 도서관, 이벤트 광장의 기능 | 기획서의 MVP에서 배경만 두는 구역이다 |
| 캐릭터 외형 선택, 맵 채팅, 상태 표시, 감정 표현 | 확장 계획이다 |
| 휴대폰 화면 대응 | 키보드로 캐릭터를 움직이는 서비스다. 기준 화면은 1440x900이다 |
| 자동화 테스트 (화면) | 팀과 합의가 끝난 뒤에 붙인다. 시청 구간 측정과 통신 코드에는 단위 테스트를, 모의 서버에는 흐름 확인 스크립트를 두었다 |
| 와이어프레임(Figma)과 대조 | 접근 권한이 없어 열지 못했다. 방향이 정해지면 대조한다 |

## 확인받은 것과 남은 것

PoC 단계에서 아래 여섯 가지를 물었고, 2026-11-20에 "방향이 좋다"는 답을 받아 그대로 진행했다.

1. 시험만 화면 전체로 띄우고 나머지는 맵 위의 창으로 띄운다.
2. "지금 할 일"로 다음 한 가지를 알려 준다.
3. 본문은 픽셀 글꼴이 아닌 고딕으로 쓴다.
4. 사용자마다 다른 캐릭터를 회원 번호로 배정한다.
5. 팀원의 맵 위에 쌓는다.
6. 모의 서버를 Vite 플러그인으로 둔다.

5번은 사용자 한 사람의 확인만으로 끝나지 않는다. 맵 담당 팀원의 파일을 고쳤고 이벤트를 추가했으므로 그 팀원의 확인이 필요하다. 남은 합의는 [확인이 필요한 것](../open-questions.md)에 있다.
