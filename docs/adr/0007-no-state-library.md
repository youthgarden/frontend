# ADR 0007: 상태 관리와 서버 데이터 라이브러리를 넣지 않는다

- 상태: 일부 바뀜. "서버 데이터 라이브러리를 넣지 않는다"는 [ADR 0009](0009-api-module-own-client-and-tanstack-query.md)에서 바뀌었다. 아래 "다시 검토할 신호"가 나타났기 때문이다. "상태 관리 라이브러리를 넣지 않는다"는 그대로다
- 날짜: 2026-11-20

## 배경

화면이 다루는 서버 데이터는 내 정보, 강의 5개, 과제 5개, 응시 하나 정도다. 여러 화면이 함께 보는 값은 내 레벨과 강의·과제 현황뿐이다. 저장소의 의존성은 React, Phaser, Tailwind가 전부다.

## 결정

Redux, Zustand 같은 상태 관리 라이브러리와 TanStack Query 같은 서버 데이터 라이브러리를 넣지 않는다.

- 여러 화면이 함께 보는 값(로그인 상태, 내 정보, 강의 현황, 과제 현황)은 `src/session/SessionProvider.tsx`의 React Context 하나에 둔다.
- 한 화면만 쓰는 값(강의 상세, 응시, 대화)은 그 화면이 직접 불러와 자기 상태로 가진다.
- 모든 요청은 `src/api/client.ts`의 `request` 함수를 지난다. 토큰 붙이기, 만료 시 재발급, 에러 해석이 여기에만 있다.
- 창을 닫을 때 `App.tsx`가 강의·과제 현황을 다시 불러온다. HUD와 창의 숫자가 어긋나지 않게 하는 장치는 이것 하나다.

## 검토한 선택지

| 선택지 | 버린 이유 |
|---|---|
| TanStack Query | 캐시와 자동 재요청이 편하지만, 데이터가 적고 화면이 창 단위로 열고 닫혀서 얻는 것이 작다. 팀이 배워야 할 것이 늘어난다 |
| Zustand | Context 하나로 충분한 크기다 |

## 결과

- 불러오는 중, 실패, 다시 시도를 화면마다 직접 처리한다. 같은 모양의 코드가 반복된다.
- 다시 검토할 신호: 같은 데이터를 세 곳 이상에서 따로 불러오기 시작할 때, 또는 "창을 닫을 때 다시 불러오기"로는 화면의 숫자가 맞지 않는 경우가 생길 때.
