# ADR 0005: 캐릭터의 생김새는 회원 번호로 정한다

- 상태: 적용 (방향 확인받음, 2026-11-20). 외형을 서버에 저장하는 일은 백엔드와 합의 필요
- 날짜: 2026-11-20

## 배경

키트에는 기본 캐릭터 20명이 있다. 기획서의 MVP 범위는 "기본 캐릭터 하나"이고, 외형 선택은 확장 계획이다. API에도 외형을 담는 필드가 없다. `GET /users/me`와 WebSocket의 접속자 정보는 `user_id`, `nickname`, `level`만 준다.

그런데 멀티플레이에서 모든 사용자가 같은 얼굴이면 모자 색과 이름표 말고는 서로를 구분할 수 없다. 내 캐릭터가 어디 있는지 찾기도 어렵다.

## 결정

`회원 번호 % 20`으로 키트의 기본 캐릭터 20명 중 하나를 고른다. 규칙은 `src/character.ts`의 `characterSpec` 함수 한 곳에만 둔다.

- 같은 회원은 로그인 화면 이후의 모든 화면(HUD, 맵, 레벨업 연출)과 다른 접속자의 화면에서 같은 모습으로 보인다.
- 서버와 API를 바꾸지 않는다.
- 레벨은 생김새와 별개로 모자 색에만 반영한다.

## 검토한 선택지

| 선택지 | 버린 이유 |
|---|---|
| 모두 같은 캐릭터 (기획서 MVP 그대로) | 접속자를 구분하기 어렵다. 키트가 준 20명을 쓰지 않게 된다 |
| 가입할 때 고르게 하기 | `user` 테이블과 API에 필드가 필요하다. 확장 계획의 범위다 |
| 브라우저에 저장해 두고 고르게 하기 | 다른 사람 화면에는 내가 고른 모습이 보이지 않는다 |

## 결과

- 사용자가 생김새를 고를 수 없다. 마음에 들지 않아도 바꿀 방법이 없다.
- 외형 선택 기능이 생기면 `characterSpec` 안만 바꾼다. 그때 필요한 것: `user`에 외형 필드 추가, `GET /users/me`와 WebSocket 접속자 정보에 그 필드 포함 (백엔드와 합의 필요).
- AI 시험관은 키트에 전용 그림이 없어서 골드 모자를 쓴 캐릭터(`EXAMINER_SPEC`)로 대신한다. 전용 그림이 오면 교체한다.
