# ADR 0003: 화면은 맵 한 장 위에 겹쳐 띄우고, 주소 이동(라우터)은 두지 않는다

- 상태: 적용
- 날짜: 2026-11-20

## 배경

기획서는 "하나의 맵에 구역이 펼쳐져 있고, 건물 안으로 들어가지 않고 화면 전환도 없다"고 정한다. 강의와 시험은 맵에서 `F` 키를 눌러 연다. 팀원의 맵도 패널을 맵 위에 띄우는 구조다.

실제 맵은 강의실과 시험장을 건물 안 화면으로 나눴다([ADR 0006](0006-build-on-teammate-branch-and-event-contract.md)). 이것은 Phaser 안에서 장면이 바뀌는 것이고, 이 문서가 다루는 React 화면의 구성과는 별개다. 광장이든 건물 안이든 React 쪽에서는 "맵 한 장"이다.

## 결정

1. 로그인한 뒤의 화면은 **맵 한 장과 그 위에 겹쳐 뜨는 창**으로만 이루어진다. React Router 같은 주소 이동 라이브러리를 넣지 않는다.
2. 로그인 전(로그인·회원가입)과 로그인 후(맵)는 로그인 상태 하나로 갈린다.
3. 큰 창은 한 번에 하나만 뜬다. 어떤 창이 떠 있는지는 `src/App.tsx`의 상태 하나(`overlay`)가 가진다.
4. 창의 모양은 내용에 따라 둘로 나눈다.

| 창 | 모양 | 이유 |
|---|---|---|
| 강의 대시보드, 강의 재생, 시험관 메뉴, 과제 목록, 과제 안내, 결과, 지난 결과, 첫 입장 안내 | 맵이 뒤에 비쳐 보이는 창 | "맵 안에서 연 창"이라는 맥락이 유지된다. 닫으면 바로 그 자리로 돌아온다 |
| 시험 진행 | 화면 전체를 덮는 화면 | 30분 동안 자료를 읽고 글을 쓰는 곳이다. 세 영역(과제·자료, AI 대화, 답안)에 화면 전체가 필요하고, 뒤에서 움직이는 캐릭터는 방해가 된다 |

5. 창이 하나라도 떠 있으면 캐릭터가 멈춘다. 창이 스스로 이 사실을 맵에 알린다(`useMapLock`).

## 검토한 선택지

| 선택지 | 버린 이유 |
|---|---|
| 강의와 시험을 별도 주소(`/lectures`, `/exam`)의 화면으로 만들기 | 기획의 "화면 전환 없음"과 어긋난다. 화면을 옮길 때마다 맵과 멀티플레이 연결을 다시 만들어야 한다 |
| 시험도 맵 위의 창으로 띄우기 | 세 영역을 창 안에 넣으면 각 영역이 너무 좁아진다 |

## 결과

- 새로고침하면 언제나 맵에서 시작한다. 풀던 시험은 서버에 남아 있으므로, 시험관에게 다시 말을 걸면 이어 풀 수 있다. 명세의 `GET /attempts/current`가 이 흐름을 전제로 한다.
- 브라우저의 뒤로 가기는 창을 닫지 않는다. 창은 `Esc`와 닫기 버튼으로 닫는다.
- 특정 화면으로 바로 가는 링크(예: 결과 화면 공유)는 만들 수 없다. 기업용 리포트처럼 링크가 필요한 기능이 생기면 그때 라우터를 다시 검토한다.
