# ADR 0008: 강의 영상 재생기를 한 겹 감싸고, 영상이 없을 때는 재생을 흉내 낸다

- 상태: 적용 (방향 확인받음, 2026-11-20)
- 날짜: 2026-11-20

## 배경

명세는 강의를 유튜브 IFrame Player API(웹 페이지 안에 유튜브 재생기를 넣고 코드로 조작하는 공식 방법)로 재생하고, 실제로 재생된 구간을 10초마다 서버에 보고하라고 정한다. 수강률은 "실제로 본 구간의 합 ÷ 영상 길이"이고 80% 이상이면 수강 완료다.

그런데 강의 영상 5개는 팀이 직접 만들 예정이고 아직 없다. 영상 ID가 없으면 재생 화면도, 시청 구간 측정도 확인할 수 없다.

## 결정

재생기를 하나의 약속(재생, 일시정지, 현재 위치 조회, 위치 이동, 상태 변화 알림, 정리)으로 감싸고 구현을 둘 둔다.

| 구현 | 쓰는 때 | 동작 |
|---|---|---|
| 유튜브 재생기 | 영상 ID가 일반 값일 때 | 유튜브 IFrame Player API를 그대로 쓴다. 실제 서비스에서 쓰는 구현이다 |
| 흉내 재생기 | 영상 ID가 `mock:`으로 시작할 때 | 영상 없이 재생·일시정지·탐색 막대만 있다. 재생 중에는 실제 시간과 같은 속도로 위치가 흐른다 |

시청 구간을 재고 서버에 보고하는 코드는 재생기 구현과 분리돼 있어서, 두 구현이 같은 코드를 탄다.

모의 서버의 강의 데이터는 1번 강의만 실제 유튜브 영상(임시 영상)을 가리키고, 2~5번은 `mock:` 값을 가진다. 두 경로를 모두 확인할 수 있다.

## 검토한 선택지

| 선택지 | 버린 이유 |
|---|---|
| 다섯 강의 모두 임의의 유튜브 영상으로 | 강의와 무관한 영상이 다섯 개 뜬다. 인터넷이 없으면 아무것도 확인하지 못한다 |
| 재생 화면을 영상이 준비될 때까지 미루기 | 시청 구간 측정과 80% 완료 처리가 이 서비스의 핵심 규칙인데 확인할 방법이 없어진다 |

## 결과

- 실제 영상이 준비되면 강의 데이터의 영상 ID만 바꾼다. 화면 코드는 그대로다.
- 흉내 재생기는 배포 코드에 남는다. `mock:` 값은 모의 서버만 주므로 실제 서비스에서는 실행되지 않는다. 불편하면 영상이 모두 준비된 뒤 지운다.
- 1번 강의의 임시 영상은 강의 내용과 무관하다. 검수하는 사람이 오해하지 않도록 [모의 서버 문서](../mock-server.md)에 적어 둔다.
- 80%를 채우려면 영상을 실제로 그만큼 봐야 한다. 서버가 "실제로 흐른 시간보다 많이 본 것으로 보고할 수 없다"는 규칙을 적용하기 때문이다. 검수할 때는 모의 서버 조작판의 "수강 완료 처리"를 쓴다.
