# ADR 0002: 픽셀 키트는 원본 그대로 복사해 두고 타입만 따로 붙인다

- 상태: 적용
- 날짜: 2026-11-20

## 배경

"청년 유치원 픽셀 키트"는 캐릭터, 타일, 오브젝트, 감정 아이콘을 **그림 파일이 아니라 코드로 그리는** 자바스크립트 모듈이다. 캐릭터 한 명은 외형 정보(피부, 머리 모양, 가방, 레벨 등)를 넣으면 48x64 크기의 그림으로 만들어진다. 레벨이 오르면 `level` 값만 바꿔 다시 그리면 모자 색이 바뀐다.

키트는 저장소 루트의 `청년 유치원 픽셀 키트/` 폴더로 전달됐다. 맵 담당 팀원이 그 소스를 `src/game/pixel-kit/`에 원본 그대로 넣고 `allowJs`(TypeScript가 자바스크립트 파일을 함께 읽게 하는 설정)를 켰다. 프로젝트는 TypeScript의 strict 모드를 쓴다. 키트는 앞으로도 디자인 쪽에서 새 버전이 올 수 있다.

## 결정

1. 키트의 `.js` 9개 파일은 팀원이 둔 `src/game/pixel-kit/`의 것을 쓰고 **한 글자도 고치지 않는다.** (PoC 때는 `src/pixel-kit/`에 따로 복사했으나, 같은 파일이 두 곳에 있게 되어 지웠다. 두 곳의 파일이 완전히 같은 것을 확인했다.)
2. 타입은 `src/game/pixel-kit/index.d.ts` 한 파일에 손으로 쓴다. 화면과 맵이 실제로 쓰는 것만 선언한다. 같은 이름의 `.d.ts`가 옆에 있으면 TypeScript는 `.js`에서 추론하지 않고 이 선언을 쓴다.
3. 화면과 맵은 키트를 직접 부르지 않고 얇은 연결 지점을 거친다.
   - 캐릭터 외형 규칙: `src/character.ts`
   - React 화면에서 그리기: `src/ui/kit/PixelCharacter.tsx`
   - Phaser 맵에 등록하기: `src/game/` 안의 연결 코드

## 검토한 선택지

| 선택지 | 버린 이유 |
|---|---|
| 키트를 TypeScript로 옮겨 쓰기 | 새 버전이 올 때마다 다시 옮겨야 한다. 옮기는 과정에서 그림이 달라져도 알아채기 어렵다 |
| `allowJs`의 추론에만 맡기기 | 외형 정보가 사실상 아무 값이나 받는 타입이 된다. `level`에 문자열을 넣어도 잡지 못한다. 그래서 `allowJs`는 켜 둔 채로 선언 파일을 덧붙였다 |
| 그림을 PNG 스프라이트로 미리 뽑아 쓰기 | 캐릭터 20명 × 레벨 6단계 × 표정을 모두 뽑아야 한다. 레벨업 때 모자 색만 바꾸는 키트의 장점이 사라진다 |
| 루트의 한글 폴더를 그대로 import하기 | 빌드 범위(`src`) 밖이다. 경로에 공백과 한글이 있어 도구마다 다르게 동작할 위험이 있다 |

## 결과

- 새 키트가 오면 `src/game/pixel-kit/`의 `.js` 파일을 덮어쓰고, 내보내는 항목이 바뀐 경우에만 `index.d.ts`를 고친다.
- 키트는 Phaser 3 기준으로 작성됐고 프로젝트는 Phaser 4를 쓴다. 확인해 보니 텍스처, 타일, 오브젝트, 캐릭터 등록은 그대로 동작했고 **외형 갱신 함수 `updateCharacter`만 동작하지 않았다.** 쓰는 중인 그림을 먼저 지우는 순서 때문에 Phaser 4에서 화면이 멈춘다. 키트는 고치지 않고 `src/game/character/kit.ts`의 `updateCharacterSprite`가 같은 그림판에 새 그림을 덮어 그리는 방식으로 대신한다. **맵에서 키트의 `updateCharacter`를 직접 부르면 안 된다.**
- 그림을 실행 중에 그리므로 첫 화면에서 캐릭터와 타일을 그리는 시간이 든다. 접속자가 많아질 때의 비용은 측정하지 않았다 (확인 필요).
- 루트의 `청년 유치원 픽셀 키트/` 폴더는 이번 변경에 포함하지 않는다. 미리보기 화면(`index.html`)을 저장소에 둘지는 팀이 정한다.
